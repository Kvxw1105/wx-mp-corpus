# 验证案例：公众号「概念因子」历史文章全量采集（2026-10-06/07）

首个全流程验证案例。任务：采集「概念因子」的历史文章 —— 全部文章列表 + 阅读量 + 正文，
**不付费、不用第三方采集工具**。

## 规模

| 阶段 | 数量 |
|---|---|
| 列表收割 | 42 篇（标题/阅读/赞/日期） |
| 正文采集 | 30 篇全文（1000-3200 字/篇） |
| 四位数文章 | 9 篇，其中 6 篇已获全文 |
| 配图下载 | 30 张（图集类文章的 `cdn_url`） |
| 归档标准化 | 30 篇（去重 + 日期统一 + 元数据补全） |
| 内容研究 | 55 位学者 / 57 条概念 / 30 个案例 |
| 研究报告 | 1 份，12 章，含 2 张交互图表 |
| 账号状态 | 采集过程中被登出一次（见下），重新登录后恢复 |

## 产出

- `out/articles_clean/` —— 30 篇标准化单篇
- `out/概念因子-全文合集.md` —— 可通读全文合集（135 KB）
- `out/概念因子-内容研究报告.html` —— 内容研究报告

## 过程中确认的平台边界

1. **正文抓取不需要登录**。带 `chksm`（值任意）+ 普通 Chrome UA 即可拿全文；
   反过来，伪装微信 UA 会直接 302。
2. **`sn` 不可绕过**。无 sn / 假 sn 一律返回约 31756 字节空壳，HTTP 200 不报错
   （静默失败，极易误判成功）。盲扫 mid 全部无效。
3. **只有列表收割需要登录态**（`getmsg` 接口要 session）。
4. **图集类文章内容在图里**。正文只有 ~90 字（歌词 + 话题标签），主体是 6 张
   1242×1656 的图文卡片 —— 必须下 `cdn_url`。
5. **`og:description` 是双层转义**，解序顺序错会让"正文"字数虚高（2413 字里 2000 字是 HTML 垃圾）。
6. **反复抢前台 + 输入注入会触发安全机制**，账号被登出。这是 GUI 收割路径的真实成本。

## 关键分析发现

**阅读量高 ≠ 内容更好。**

| | 篇数 | 平均赞率（Σ赞/Σ阅读） |
|---|---|---|
| 爆款（≥1000 阅读） | 9 | **3.70%** |
| 非爆款 | 33 | **8.10%** |

爆款赞率只有非爆款的一半。爆款被外部流量推高、读者泛化，认同度被稀释。
→ 筛选文章时用"阅读 × 赞率"交叉，只看阅读量会挑错。

**爆发是阶段性的**：成长期均值 331 → 爆发期均值 850（2.6 倍），6 篇爆款集中于此；
且出现连续 5 篇全爆款的集群效应（不像自然增长）。回落期赞率反升至全周期最高，
说明核心读者黏性好，但流量天花板始终未突破。

## 耗时分布（约值）

- 列表收割：GUI 自动化，跨多批次 ≈ 2h（含被登出后重新登录）
- 正文抓取：30 篇纯 HTTP ≈ 5min（不需要登录，速度快）
- 配图下载：30 张 ≈ 2min
- 归档标准化：脚本一次跑完 ≈ 1min
- 内容研究：两路并行 agent 精读 + 知识提取 ≈ 1h
- 报告生成与验证：≈ 0.5h

**对比**：正文抓取是纯 HTTP，30 篇 5 分钟；列表收割要 GUI 自动化，42 篇花 2 小时。
**登录态是瓶颈，HTTP 不是。**
