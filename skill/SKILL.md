# wx-mp-corpus · 微信公众号语料采集与内容研究

把"采集一个公众号"变成可复现流水线。四段链路，**每段可独立复用**：

```
① 列表收割（要登录态）  →  ② 正文抓取（不要登录态）
        ↓                              ↓
③ 归档标准化（已知输入直接跑）  →  ④ 内容研究与报告
```

---

## 0. ★★★ 最重要的一条：正文抓取的真相（必读）

**URL 带 `chksm` 键（值任意）+ 普通 Chrome UA = 拿到任何有 `sn` 的文章全文。与 IP / 登录态 / Cookie 全无关。**

```
https://mp.weixin.qq.com/s?__biz=..&mid=..&idx=..&sn=..&chksm=<任意值，64个0也行>
UA: Mozilla/5.0 (Windows NT 10.0; Win64; x64) ... Chrome/120.0.0.0 Safari/537.36
```

三条铁律：

1. **`chksm` 值随便填**。服务端只判断"有没有这个键"（链路指纹），不校验值。
   有 `sn` 但没 `chksm` → **302 未知错误**。
2. **必须用普通浏览器 UA**。★ 伪装 `MicroMessenger` 微信 UA **会被拒绝**（302）。
   网上"必须伪装微信 UA"的说法**是错的** —— 那些项目把 `chksm` 有无和 UA 两个变量混在一起了。
3. **`sn` 不可绕过**。无 sn / 假 sn → HTTP 200 但只有约 **31756 字节的空壳**。
   ★ **判定信号：`len ≈ 31600` 且响应里没有 `id="js_content"` = sn 不对**。
   服务端静默失败，不报错，极易误判成"成功了"。

> **反模式警告**：遇到 302 先去查 IP、换代理、找绕过工具 —— **全都是白费**。
> "公网 IP 被微信拉黑"这个判断**从未成立**。302 一律先检查 `chksm` 和 UA。

**→ 唯一真正需要登录态的环节是列表收割**（`profile_ext?action=getmsg` 无 session 时返回
`{"errmsg":"no session"}`）。正文抓取完全不需要登录。

## 1. 列表收割（需要登录态，GUI 自动化）

### 通道
微信 PC 客户端内置浏览器（`Chrome_WidgetWin_0` / `Qt51514QWindowIcon`）。
无地址栏（Ctrl+L 无效）、Ctrl+A/C 被禁用、右键菜单**无"复制链接地址"**。

### 抢焦点才是真瓶颈
**`SetForegroundWindow` 从后台进程调用会静默失败**，症状是**所有后续鼠标/键盘输入全部无效**
（点击不动、滚轮不滚、按键无反应），**极易误判成"坐标算错"**。

入场先做焦点校验：
```python
# 重试 + 校验 GetForegroundWindow() == hwnd
# 顺序：ALT 键解锁 → AttachThreadInput → BringWindowToTop → 校验
```
校验不过就停，不要继续发输入 —— 后面的点击全是无效的。

### 窗口规矩（双屏机器必须遵守）
- **自动化窗口一律放副屏**（x ≥ 主屏宽度），禁止占用主屏。
- **不要为了截图把窗口拖到主屏** —— 截图工具应按**窗口矩形**抓
  （`ImageGrab.grab(bbox=窗口rect, all_screens=True)`），窗口在前台与否都能抓。
- ★ 只按主屏裁剪的截图函数在窗口位于副屏时会算错（`right < left` → ValueError）。**副屏窗口用按窗口矩形抓的那个**。
- 用户可能正在用主屏，任何抢焦点/置顶/移动主屏窗口的操作都会打断他。

### 窗口句柄会变
`hwnd` **不固定**（重开/换标签会变）。**每次先枚举当前窗口，不要复用旧值。**

### 阅读量抓取
登录后在公众号历史消息页滚动加载，解析 `getmsg` 返回的 JSON（标题 / 阅读数 / 赞数 / 日期）。
分页累积 → 合并去重（同一篇可能多页重复）。

### 已知阻塞
**反复抢前台 + 输入注入可能触发微信安全机制 → 账号被登出**（弹「为了你的账号安全，请重新登录」）。
出现即停，交还用户手动登录，不要反复重试（会加重风控）。

## 2. 正文抓取（不需要登录态，纯 HTTP）

### 三种页面模板
| # | 模板 | 判据 | 正文位置 |
|---|---|---|---|
| 1 | 普通图文 | `rich_media_content` | `id="js_content"` |
| 2 | **图集/图片消息** | `picture_page_info_list` + `item_show_type` | `text_page_info.content`；**主体是 `cdn_url` 图** |
| 3 | 分享卡 | 仅 `og:description` | `og:description`（引文 + `#话题#`） |

`item_show_type`：**8 = 纯图，10 = 图 + 配文**。

★ 图集类短文（如"文化马赛克"卡片）正文只有 ~90 字，**内容是图，字数少不等于采集失败** —— 要下 `cdn_url`。

### 框架陷阱（务必显式关代理）
```python
s.trust_env = False
s.proxies = {"http": None, "https": None}   # ★ 只写 {} 不够，必须显式 None
s.verify = False
```
清代理逻辑要**下沉进 `fetch()` 内部**，不能依赖调用方。
症状是后台运行全 `SSLError: certificate verify failed`，前台手跑却成功 —— 典型的环境变量污染。

### `og:description` 是双层转义，解序不能错
```python
t = re.sub(r"\\x26", "&", t)       # ① \x26 -> &
t = t.replace("\\x0a", "\n")       # ② 换行
t = unescape(t)                    # ③ &lt; -> <
t = re.sub(r'<a[^>]*wx_topic_link[^>]*>(.*?)</a>', r'\1', t, flags=re.S)
```
★ **顺序错会字数虚高**：先 unescape 再删标签 → `\x26lt;a..\x26gt;` 变成真标签 →
`strip_html` 把属性当正文留下（"正文"2413 字里 2000 字是垃圾）。

### 盲扫 mid 不可行
随机试 mid 一律返回 31756 空壳。`sn` 服务端强校验，**只能从客户端点开文章时抓包拿到**。

## 3. 归档标准化（已知输入可直接跑）

### 输入
- `out/articles/*.md` —— 每篇一个文件（脚本抓取时落盘）
- `_list_merged.json` —— 权威清单，含 `title/read/like/date`
- `_index.json` —— 图集等特殊文章的索引（含 mid/sn/chars/images/card）

### 常见脏数据（必然遇到）
- **同一篇两个文件名**：`2026-03-06-x.md` 与 `3月6日-x.md` 各一份
- **日期五种写法混用**：`7月5日` / `unknown` / `星期日(约8月9日)` / `2026-10-06(今天)`
- **元数据字段数不一**：有的 5 行有的 6 行；`阅读：?　赞：?` vs `阅读：1089　赞：41`

### 标准化规则
0. **直接跑 `scripts/unify_archive.py`**，不用重写：
   ```bash
   python scripts/unify_archive.py <工作目录> [号名]
   ```
   它读 `<工作目录>/out/articles/*.md` + `_list_merged.json`（可选 `_index.json`），
   自动完成下面 1-4 条并输出标准化单篇 + 通读合集。列表清单缺失时不报错，降级为只读文件内数据。
1. **以 `mid` 为唯一键去重**。同一 mid 只留**正文字数最多**的那份（长文归档优先于短文卡片）。
2. **日期统一为 `YYYY-MM-DD`**。从 `_list_merged.json` 按标题反查；年份缺失的补当前年份。
3. **阅读/赞缺失就留 `—`，不猜**。缺失是真实状态（页面在读到数据前就被归档了）。
4. 输出两份：`out/articles_clean/`（标准化单篇）+ `out/<号名>-全文合集.md`（可通读合集）。

### 合集结构（阅读友好）
```
# <号名>·历史文章全文合集
> 共 N 篇｜采集于 <日期>｜按发布时间排序
## 阅读量四位数（重点）      ← 速览表：标题/阅读/赞/赞率/发布
## 全部目录                   ← 全量表：#/发布/标题/阅读/赞/字
---
## 1. <标题>
`日期`　阅读 **N**　赞 N　★档位　N 字
<正文>
---
```

### 关键提醒
- **字数要同时扫描所有归档来源取较大值**，否则图集类短文（正文仅几十字、内容在图里）会被误判为"未采集"。
- 中文写入用脚本文件而非 `python -c` 内联（shell 会吃反引号 + 中文乱码）。
- 打印中文乱码只是控制台编码问题，文件本身 UTF-8 正常。

## 4. 内容研究与报告

### 分析方法
1. **拆写作模板**：统计段式结构（题记 / 钩子 / 反转 / 立论 / 批判 / 收尾动作），找固定句式和签名设计。
2. **统计引用班底**：用 grep 数思想家/学者出现频次，得出分工画像（谁管什么议题）。
3. **提炼母题**：跨篇归纳重复出现的核心命题。
4. **数据交叉分析**（★ 最有价值）：
   - **用加权赞率**（Σ赞 / Σ阅读），不要算术平均 —— 否则小样本文章会拉偏。
   - **交叉阅读量与赞率**，往往能发现反直觉规律。

### ★ 实战发现（可直接作为分析假设）
在「概念因子」号上验证：**阅读量高 ≠ 内容更好**。

| | 篇数 | 平均赞率 |
|---|---|---|
| 爆款（≥1000 阅读） | 9 | **3.70%** |
| 非爆款 | 33 | **8.10%** |

爆款赞率只有非爆款的一半。解释：**爆款被外部流量（平台推荐/大号转发）推高，读者泛化，认同度稀释**。
→ **建议筛选文章时用"阅读 × 赞率"交叉，只看阅读量会挑错。**

另一发现：**爆发是阶段性的**（某段时期均值是前期的 2.6 倍），且出现**连续多篇全爆款**的集群效应
（不像自然增长，更像被推荐/转发带起来的一波），赞率在回落期反而升到全周期最高 → 核心读者黏性好但流量天花板未破。

### 报告形态
单文件 HTML，`--color-*` CSS 变量，含 Chart.js 图表（阅读分布柱状图 + 时间双轴）。
★ Chart.js 的 `<script src>` 必须在使用它的 `<script>` **之前**。生成后**用 headless 截图验证渲染**。

## 6. 边界

- 不绕登录、不破解风控、不并发请求、不互动（只读）。
- **采集失败要区分"平台限制"和"自己的 bug"**：31756 空壳 = sn 不对（自己的问题）；
  没有 `sn` 来源 = 必须先登录点开（平台的墙）。不要混为一谈。
- 账号被登出 → 立刻停，交还用户手动登录，不反复重试。
- 数据缺失如实标注 `—`，不猜、不补。
